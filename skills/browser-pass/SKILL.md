# Browser pass

**Rules first.** Read `CLAUDE.md` in the plugin root and follow it. This pass is
read-only: never click save, send, publish, approve, delete, or anything in
Settings; never leave typed text in a field; never copy names, emails, or
message text of real people into files.

Locate the plugin root (the folder holding `context/` and `tools/`). Follow
`docs/browser-pass.md` there; this skill adds the steps below. If Claude in
Chrome isn't connected or the SE isn't logged in, stop and say so. Never try to
sign in.

## Steps
1. Confirm the account switcher shows **Secure Patient Technology** (see
   `context/tenant-baseline.md`). If not, stop and ask.
2. Walk, read-only, one screenshot each: Publishing calendar (month view),
   Composer (open, close without saving), Approvals, Smart Inbox, Listening
   (every topic in the SPT group), Reports (list of report names), Trellis
   (open only).
3. Inject `tools/overlay/overlay-engine.js` (the fixed copy) with the
   javascript tool, then run `__demoTailor.scan()` and `__demoTailor.cssPath()`
   on each screen. Include **Listening** and **Reports**, not only the
   standard screens. Never guess selectors; record what scan returns.
4. Write `context/tenant-index-ui.md` (same style as `tenant-index.md`, with a
   "Generated by the browser pass, <date>" line) and update
   `context/click-paths/app-map.json` for each screen's selectors. Prefer
   `data-qa` attributes over hashed classes.
5. Check: every report and screen name written must be visible in a screenshot.
6. Revert the overlay (`__demoTailor.revert()`), then tell the SE what changed.
