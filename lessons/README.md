# Lessons

One short note per lesson. Read these before changing the overlay, the
selectors, or the tests, so a problem we already paid for isn't paid for twice.

- One lesson per file. The first line is a one-sentence summary.
- Say what happened, why it mattered, and what to do instead.
- Record what worked as well as what failed.
- Update a note when you learn more. Delete it if it turns out to be wrong.
- Don't repeat what the code, the tests, or git history already say.
- Keep notes prospect-neutral. Anything about one prospect belongs in `runs/`.
