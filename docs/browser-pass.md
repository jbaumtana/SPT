# Browser pass: record what the API can't see

Run once from a Claude session **on your computer** with Claude in Chrome
connected and this repo open. Redo it only when the tenant or Sprout's UI
changes. About 15 minutes. Read-only: nothing is clicked that saves, sends,
publishes, or deletes.

## Paste this into the local session

> Read CLAUDE.md and docs/browser-pass.md, then do the browser pass. I'm logged
> into Sprout in Chrome.

## What the session does

1. **Confirm the tenant.** The account switcher must show Secure Patient
   Technology. If not, stop and ask.
2. **Walk these screens, read-only,** and take one screenshot of each:
   Publishing calendar (month view), Composer (open and close without saving),
   Approvals, Smart Inbox, Listening (each topic in the SPT group), Reports
   (the list of report names), Trellis (open it; don't ask anything).
3. **Record what it found:**
   - `context/tenant-index-ui.md`: hand-off file in the same style as
     `tenant-index.md`, with a "Generated by the browser pass, <date>" line:
     - Report names exactly as listed in Reports
     - Whether Trellis is available, and where it opens from
     - Publishing calendar: how many weeks have items, which campaigns appear, any item showing a real company name
     - Smart Inbox: rough volume and message types for the SPT profiles
     - Anything on screen that belongs to another team's demo
   - `context/click-paths/app-map.json`: for each screen, the CSS selectors the
     overlay needs (brand name, profile avatar, calendar caption, approval
     caption), found with `__demoTailor.scan()`. Never guess selectors.
4. **Check its own work:** every report and screen name it wrote must be
   visible in a screenshot. Then commit both files on the current branch.

## Never

- Click save, send, publish, approve, delete, or anything in Settings
- Type into a field and leave it saved
- Copy user names, emails, or message text from real people into the repo
